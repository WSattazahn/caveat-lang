# Event phase instrumentation boundaries

Profiling only. The feature adds no eligibility, removal, storage, save, reason, archive ordering, admission or rollback algorithm changes. No production scopes or existing explicit drop points move. All hooks and the module are native-only `event-phase-profile`; the feature enables existing `collector-metrics` but neither per-record diagnostic feature. `event-phase-origins` enables phase locations and counters while compiling out every recorder `Instant` import/read.

The public API is `ReactiveSession::begin_event_phase_profile()` / `take_event_phase_profile()`, `EventPhaseProfile { clock_enabled, phase_ns, phase_entries, transitions }`, `EventPhase`, `EVENT_PHASE_COUNT = 11`, `EVENT_PHASE_NAMES`, and `current_event_phase_index()`. The allocator query uses separate constant-initialized `Cell` TLS, no heap/RefCell/lock, and `try_with` falls back to Outside at teardown. The recorder is fixed-size TLS outside session state; rejected work remains readable. Begin/take are a harness contract outside runtime scopes.

| Index/name | Actual boundary |
|---|---|
| 0 outside | Allocation tag only; not timed by the runtime. The harness must report its outer elapsed minus summed phase times as an explicit residual, not claim zero outside cost. |
| 1 transaction_preparation | Starts at `apply_classified` entry (`reactive.rs:3395`): event/input/identifier checks, moving shown/archive aside, shallow session clone, restoration of original archive and staging identifiers. Resumes briefly after `run_event` returns. |
| 2 evaluation | Starts at `run_event` entry (`reactive.rs:3530`): collector begin, previous effects/cues reset, sequence/clock changes, due qualifications, parameter tracking, rule evaluation/effects. Resumes briefly after departure returns. |
| 3 collection | Starts at `depart_unpinned` entry (`reactive_departure.rs:590`): debug audits where enabled, retirement candidates and withdrawal collector resolution. An empty departure returns here. |
| 4 compaction | After a nonempty departing set (`reactive_departure.rs:620`): holder bookkeeping and full phase-1 provenance compaction. |
| 5 archive_construction_and_removal | Existing phase2 start (`reactive_departure.rs:822`): graph/identity snapshots and removal, observations, withdrawal extraction, per-record qualifications/history removals/archive construction, journal handover, final history/numeric archive ordering, collector departure update, audits and departure-local buffer destruction. These operations are interleaved; this is not an archive-only cost. |
| 6 binding_evaluation | After departure (`reactive.rs:3591`): change detection, final bindings and debug verification; binding failure returns without settlement. |
| 7 final_settlement | Immediately before `settle_archive_provenance(Some(old), true)` (`reactive.rs:3598`): archive provenance traversal/publication plus existing scope-end destruction of `run_event` locals (including parameters, change tracking and rule/index Arc handles). Thus it is settlement-and-final-frame-cleanup, not a pure single-function timer. |
| 8 commit_cleanup | Success arm (`reactive.rs:3505`): archive append, `*self = next` including original-session destruction, archive restoration and function-local cleanup. |
| 9 rollback_cleanup | Error arm (`reactive.rs:3514`): return shown data and implicit staged-session destruction, while original archive/session remain unchanged. Early input rejection has no staged transaction and stays preparation. |
| 10 apply_wrapper | Public numeric `apply` entry (`reactive.rs:3379`), resuming after the classified call: includes conversion of classified errors to Strings. |

Each guard is declared before its measured locals. Rust drops those locals before the guard restores its parent phase; no extra explicit drop changes lifetimes. A single timestamp closes/opens adjacent timing slices, so phases are exclusive. Hook work either side of that timestamp belongs to its adjacent phase; outer-entry/exit overhead remains residual. Successful departure has13 fixed transitions including parent resumptions and final Outside; an empty departure has11, unknown-event rejection4, and final-binding rejection after departure12. These counts do not scale with records. Entries count resumptions, not just logical function calls.

Consumer scope: `dispatch` calls numeric `apply`, whereas classified JSON/outcome/view dispatches call `apply_classified` directly (`reactive.rs:3235,3276,3637`). Their payload parsing and resulting view/snapshot serialization are outside these inner phase guards; the registered experiment uses numeric `apply`. Restoration calls `settle_archive_provenance(None,false)` separately (`reactive_save.rs:714`) and is not attributed as an event. `run_event` is the sole caller of `depart_unpinned` and the event settlement call. Existing timing/counter diagnostics remain independent and must stay disabled in the registered timing/origin builds.

Focused tests cover disabled/reset lifecycle; early input and rule rejection; fixed counts for empty and nonempty departure; successful release; final-binding rollback with undrained archive; and RAII parent restoration after a staged-local destructor observes rollback phase. Both feature modes must run these checks; origin records must contain zero measured times with `clock_enabled = false`. Full source/protocol identity and end-to-end allocator validation belong to the final freeze/gates. No performance attribution is established by this source note.
