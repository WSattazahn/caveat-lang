# CAVEAT Language 0.1.0-rc.18 — taking back a late qualification, ordered explanations, and what `explain` observed

**Release candidate, not yet published.** This file holds the release notes for 0.1.0-rc.18 while the candidate goes through `publish-npm.yml`, as rc.12 to rc.17 did. The tag, the tested artifact and the npm publication are recorded below only after the workflow's `verify-publication` job passes. The scope is the [rc.18 plan](https://github.com/WSattazahn/caveat-lang/blob/main/docs/releases/rc18-development.md), which answers Glowcap round 8 and the first agent pilot's four issues, with the owner's decisions Q1 B, Q2 A, Q3 B and Q4 A.

## Taking back a late qualification

`unqualify EVIDENCE with CAVEAT` takes back what `qualify` added ([Take-back 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-take-back-0.1.md), [PR #203](https://github.com/WSattazahn/caveat-lang/pull/203), [PR #210](https://github.com/WSattazahn/caveat-lang/pull/210)). It reaches every held occurrence of the evidence, including the occurrence before a `renew`. That is what round 8's CR20 needed: a doubt placed on a witness, the witness renewed, then the doubt taken back.

- A take-back is a recorded event, not a deletion. The `qualifies` relation stays in the graph, and the session's `taken_back` list gains a record naming the evidence, caveat, sequence and event.
- Current values drop the caveat unless another live relation still carries it, or a stored record kept it. A commitment's basis and grounds never change, nor does anything already recorded in the journal, archives or decision series.
- A caveat that some `unqualify` names may only be applied by `qualify`. The load rules say what else it may not do. There is no new refusal code. A take-back with nothing to take back is not a failure.
- `qualify` after a take-back applies the caveat again.
- `proofs/lean/Caveat/Late.lean` gains a take-back step, with laws showing a take-back leaves every commitment's basis and grounds equal and every value's number unchanged.

A program that does not use `unqualify` is unchanged. When the profile was specified, no tracked program used the word.

## View 0.2 lists binding evidence in the order it was first observed

Each binding explanation in View 0.2 now lists its evidence in first-observed order, the rule commitment grounds already used ([PR #205](https://github.com/WSattazahn/caveat-lang/pull/205)). Caveats stay sorted. Nothing new is saved: the order comes from what a save already keeps. View 0.1 is unchanged byte for byte. The full-corpus delta gate passed on that change: 150 programs, 77,927 accepted events, 2,930 restores, and 124,352 of 124,352 deliberately corrupted deltas caught.

View 0.2 and its delta gain `taken_back` only in a program that takes back.

## `explain` shows what observed each ground

Under "based on", `caveat explain` now names the event, with its payload, that observed each piece of evidence a decision rests on ([PR #206](https://github.com/WSattazahn/caveat-lang/pull/206), [#199](https://github.com/WSattazahn/caveat-lang/issues/199)):

```text
      rain_chance@1: observed at #1 read_forecast {"chance":70}
```

A ground observed before the events `explain` was given says so. The JSON report adds `observed_by` to each revision, an additive field on `caveat-explain/0.1`. This is a kit change only, with no runtime, save or language change.

## A trap from exhausted memory names its cause

A host that opened sessions without closing them could run the runtime out of WebAssembly memory, and the trap said only "unreachable". The error now says memory ran out, with the number of sessions opened and not closed, and that the runtime must be loaded again ([PR #207](https://github.com/WSattazahn/caveat-lang/pull/207), round 8 item 7). The kit README says why to close sessions.

## The compatibility promise

[docs/COMPATIBILITY.md](https://github.com/WSattazahn/caveat-lang/blob/main/docs/COMPATIBILITY.md) is prepared for 1.0 ([PR #208](https://github.com/WSattazahn/caveat-lang/pull/208)):

- Every specification's status line says whether the promise covers it. The drafts, the games, the native-only profiles (including the semantic map), incremental evaluation and the verification record are not covered.
- `caveat check` reading single-file programs only is now written into the CLI row.
- Each promise names the CI steps that check it, and a test holds the document to the repository.
- Saves written by the published rc.17 are checked in as fixtures. CI restores them with this runtime and requires rc.17's outcomes and View 0.1 bytes. View 0.2 must match the same events played live.

Prereleases, this one included, may still change anything until 1.0.0.

## Saves

The save schema stays `caveat-reactive-save/0.1`. Saves from earlier releases restore in rc.18. A save of a program that uses `unqualify` can carry `taken_back` and `kept`, which rc.17 and earlier refuse. A save of any other program has neither field. For the three fixture programs, published rc.17 restored saves made by this candidate and gave the same View 0.1.
