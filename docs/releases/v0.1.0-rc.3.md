# caveat-lang 0.1.0-rc.3

The third release candidate of the developer kit, and the first on npm. It is
a **release candidate, not a stable release**. It was published with the npm
tag `next`. Because it is the package's first version, npm also gave it the
tag `latest` ([below](#npm-tags)). The same tarball is attached to the GitHub
pre-release [v0.1.0-rc.3](https://github.com/WSattazahn/caveat-lang/releases/tag/v0.1.0-rc.3).

```sh
npm init -y
npm install caveat-lang@next
npx --no-install caveat init
npx --no-install caveat test umbrella.scenarios.json
```

## What changed since rc.2

- **Kit commands** ([#29](https://github.com/WSattazahn/caveat-lang/pull/29)):
  - `dependents` shows what rests on a piece of evidence, a reading stream or
    a caveat;
  - `serve` keeps a session open over JSON lines
    ([Serve 0.1](../../spec/caveat-serve-0.1.md));
  - `validate`, `replay` and `init`.
- **Identifiers learned at run time**
  ([#31](https://github.com/WSattazahn/caveat-lang/pull/31)): `id`
  parameters and `id_text`.
- **Withdrawal** ([#32](https://github.com/WSattazahn/caveat-lang/pull/32)):
  withdraws an observation without erasing what rested on it.
- **Permission** ([#33](https://github.com/WSattazahn/caveat-lang/pull/33)):
  `permitted by` records what permitted a decision, apart from its grounds.
- **Declared reopening triggers**
  ([#34](https://github.com/WSattazahn/caveat-lang/pull/34)) on decision
  series.
- **A one-page reference, a tested worked example, and `caveat check`**
  ([#35](https://github.com/WSattazahn/caveat-lang/pull/35)). The check gives
  advisory warnings with stable codes
  ([Check 0.1](../../spec/caveat-check-0.1.md)).
- **Whole-number positions for typed parameters**
  ([#36](https://github.com/WSattazahn/caveat-lang/pull/36)). A fraction such
  as `1.5` for an `in` or `kind` parameter is now `input/payload_invalid`. In
  rc.2 it was accepted as a value that names no member. An exploratory
  authoring trial found it, after its submission had passed every
  pre-registered check.
- **Publishable to npm**
  ([#37](https://github.com/WSattazahn/caveat-lang/pull/37)): `private` is
  removed, the tag `next` is kept, npm metadata is added, and the install
  instructions are updated.

The authoring guide also gained a section on procedures
([#27](https://github.com/WSattazahn/caveat-lang/pull/27)). Trial write-ups and
the agent-ledger experiment
([#26](https://github.com/WSattazahn/caveat-lang/pull/26),
[#30](https://github.com/WSattazahn/caveat-lang/pull/30)) stay in the
repository and are not in the package.

## npm tags

The package was published with `npm publish <tarball> --tag next`. npm's
documentation says `--tag` keeps publishing from setting `latest`. Even so,
the registry lists `latest` as well as `next` for `0.1.0-rc.3`, because this
is the package's first version.

- In [npm/cli#8490](https://github.com/npm/cli/issues/8490), an npm CLI
  contributor confirms that a package published for the first time with any
  tag gets both that tag and `latest`.
- In the same issue, its reporter says that npmjs refused to remove `latest`
  (400 Bad Request).

The owner accepted both tags pointing at this candidate. The registry was not
changed after publication. Until another version is published, a bare
`npm install caveat-lang` also installs this release candidate.
