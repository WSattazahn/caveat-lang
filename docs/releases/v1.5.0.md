# CAVEAT Language 1.5.0

**Candidate, not yet published.** This note becomes the release record once
npm publication of caveat-lang@1.5.0 is verified.

1.5.0 is the fifth minor release of 1.x. It is cut from `main` (135 merged PRs
since 1.4.1). It adds eight stable profiles (six language profiles and two kit
profiles), one refusal code (`evaluation/unset_state`, for new syntax), two MCP
tools (`caveat_dispatch` and `caveat_find`), three opt-in `check` warnings,
opt-in `explain` and `review` flags, and `whatIf` agent support. It also
delivers the **module-binding correction** (D088, D091, D093–D097), fixes a
broad set of runtime, lineage, collection and restore validation findings
(D027–D105), removes restore's 16 MiB save-size cap (D070), and speeds up both
event dispatch and reused-view patching. The eight profiles it adds are stable
from 1.5.0 under the
[compatibility commitment](https://github.com/WSattazahn/caveat-lang/blob/main/docs/COMPATIBILITY.md).

## New in the language

- **Across Members 0.1**: `sum(for KIND as $NAME: EXPRESSION)`,
  `any(for KIND as $NAME: CONDITION)` and `all(for KIND as $NAME: CONDITION)`
  aggregate across every member of a kind without listing members by hand
  ([Across Members 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-across-members-0.1.md)).
- **Grounds Of 0.1**: `grounds_of(SERIES)` reads the current revision's value
  on its grounds alone rather than its whole basis, so a downstream decision
  carries `withdrawn` exactly when `rests_on_withdrawn(SERIES)` is true
  ([Grounds Of 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-grounds-of-0.1.md)).
- **Reading Caveats 0.1**:
  `sample STREAM = EXPRESSION ... with CAVEAT, … [when CONDITION]` puts caveats
  on that reading alone when the condition holds; the condition's lineage joins
  the reading either way
  ([Reading Caveats 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-reading-caveats-0.1.md)).
- **Thresholds 0.1**: `threshold NAME = NUMBER;` declares a named numeric bar;
  every commit that names it records the threshold and its value in its basis
  and in `explain`
  ([Thresholds 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-thresholds-0.1.md)).
- **Routed Work 0.1**: `work skips other routes;` stops top-level rules whose
  route the event payload makes false from counting against the 4,096-step
  event work limit
  ([Routed Work 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-routed-work-0.1.md)).
- **Unset States 0.1**: `state NAME unset [min A max B];` declares a state with
  no value until a rule sets it. `is_set(STATE)` tests whether it has a value;
  reading an unset state outside `is_set(…)` refuses the event as
  `evaluation/unset_state`
  ([Unset States 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-unset-states-0.1.md)).

Each new form did not load on 1.4.1, and existing identifier names remain valid.

## New in the kit and MCP

- **Find 0.1**: `caveat find DIRECTORY WORD…`, `findDecisions(…)` and the
  `caveat_find` MCP tool search past decisions by plain words across names, evidence, sources, claims, caveats and retention
  reasons, returning each matching revision with its standing and outcome
  (`caveat-find/0.1`;
  [Find 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-find-0.1.md)).
- **`caveat_dispatch` MCP tool**: continues one running ledger across stateless
  MCP calls by accepting and returning a compact save (`caveat-dispatch-step/0.1`,
  capped at 2 MiB, with optional `moduleBindings`;
  [MCP tools](https://github.com/WSattazahn/caveat-lang/blob/main/kit/docs/MCP.md)).
- **View Patch 0.1**: `session.dispatchView(event, payload, { reuse: true })`
  builds a deeply frozen `View 0.1` incrementally from a patch
  (`caveat-reactive-view-patch/0.1`), keeping every unchanged member, map entry
  and list entry identical by reference. In 1.5.0 the kit decodes a compact
  binary wire patch directly into frozen objects and fails closed as `fatal` on
  any malformed patch
  ([View Patch 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-view-patch-0.1.md)).
- **Opt-in `check` diagnostics**: `caveat check --withdrawals` reports commits
  on withdrawable sources without a withdrawal guard (`C010`) and decisions no
  withdrawal reopens (`C011`); `caveat check --names` reports a `commit` one or
  two edits from a declared decision series (`C012`)
  ([Check 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-check-0.1.md)).
- **Explanations, review and `whatIf`**: `caveat explain --later-caveats` adds
  live caveats on grounds absent from the frozen revision; `caveat explain
  --lineage-notes` marks lineage inherited from the previous revision; `explain`
  text describes each observation once and shows qualification take-backs across
  `explain`, `review` and `dependents` (D029); `caveat review --all --summary`
  counts how often retained caveats materialized across ledgers; and
  `session.whatIf(event, payload, { agent })` accepts an event agent (D027).
- **Module-binding restore option**: `moduleBindings` (`"scoped"` or
  `"legacy-hold-capture"`) is exposed across `runtime.restore`, `caveat serve`
  (`--restore-module-bindings` and per-request), `caveat_dispatch`,
  `caveat-lang/saves` and the integration starter (D094, D096, D097).

## Module-binding correction and save compatibility

Fresh loads now honor module-local `hold` and `release` references instead of
accidentally capturing a root declaration (D088, D091, D093). Affected state
and replay saves record `module_bindings` (`scoped` or `legacy-hold-capture`);
unaffected saves keep their exact bytes. Historical unmarked saves continue
automatically under their writer's interpretation whenever the save format and
source determine it — including positional replay saves from 1.2.0–1.4.1 and
pre-rc.17 state saves without `source_sha256` (D095) — and require an explicit
`moduleBindings` choice only when releases before 1.2.0 and from 1.2.0 to 1.4.1
could both have written that save format for the source and linked it
differently. See
[Save 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-save-0.1.md#module-binding-interpretation)
and [the correction review](https://github.com/WSattazahn/caveat-lang/blob/main/docs/reviews/2026-11-14-module-binding-correction.md).

## Fixed

- **Runtime evaluation and refusal boundaries**:
  - `carries` and `carries_any` reads past the provenance limit refuse as
    `limit/provenance_limit` instead of ending the session (D037).
  - Negative `qualify … after` delays refuse as `evaluation/expression` (D042);
    commits of declared commitments refuse instead of failing (D044);
    `reopened()` on unobserved evidence refuses as
    `evaluation/unobserved_evidence` (D045); `renew` refuses creating an
    occurrence colliding with a declared name as `limit/renewal_limit` (D103).
  - Relations revealed from cited evidence reach scoped bindings (D036);
    skipped `set` effects add their whole guard to target lineage (D048); the
    withdrawal collector retains records named by an outcome's lineage (D047)
    and scopes its work to what an event changed (D056).
  - Function arguments expand once (D034); relations naming evidence `agent` or
    `threshold` load again (D035); evidence source text is left unexpanded
    (D086); journal entries stay distinct from declared names or histories
    spelled `journal@K` (D074, D105); refusal messages and listings never
    depend on hash-table order; and older function, module and compiler name
    compatibility regressions are fixed (`#477`–`#479`).
- **Restore size and validation**:
  - Restore accepts state saves of any size, removing the 16 MiB cap (D070;
    hosts bound untrusted saves, as `caveat_dispatch` does at 2 MiB), and checks
    retired records in linear time (D071).
  - Hardened restore validation covers declared attention and last-event examine
    budgets (D043, D046, D053), journal/hold/retirement agreement and outcome
    lineage compaction (D038–D041, D049–D051, D060, D062), observation, stance,
    renewal, reading and relation multiplicity checks (D052, D055, D058, D059,
    D063–D065, D101, D102, D104), and per-part history and citation reachability
    across windowed and windowless programs (D054, D057, D061, D083, D098–D100).

## Performance

Event dispatch and view generation received a multi-stage optimization series
spanning compiler steps 2a/2b, runtime speed items 1–7 (`#375`, `#382`, `#399`,
`#403`, `#416`, `#422`, `#426`, `#429`–`#432`, `#437`, `#461`, `#465`–`#468`,
`#471`, `#497`–`#499`), and view-patch passes 1–6 (`#500`–`#505`), culminating in
a compact binary view-patch wire format with a direct frozen JS decoder. On
local P-core-0 AB/BA benchmarks on `main` (`c51b8d13`), WebAssembly
`dispatchView(..., { reuse: true })` median dropped to ~31.7 µs on
`release-gate` (from ~168 µs in the initial 2026-10-31 View Patch measurement)
and ~18.3 µs on `ledger` (from ~237 µs), with byte-identical corpus and save
sweeps.
