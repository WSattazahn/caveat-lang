## A save after a taken-back caveat restores

A session that reopened a decision because of a caveat, then took that caveat back with `unqualify`, wrote a save that restore refused with "reopening cites caveats unrelated to its witnesses". A starter host checkpoints after every accepted event, so such a host could not resume. [Take-back 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-take-back-0.1.md) leaves the decision journal as it was, and a save of a session the runtime ran is one it must restore ([COMPATIBILITY.md](https://github.com/WSattazahn/caveat-lang/blob/main/docs/COMPATIBILITY.md), "Saves, archives and source").

The restore check compared a reopening's caveats with the caveats its evidence carries now, which a take-back lowers. It now counts every `qualifies` relation the graph holds, marked or not, since a take-back marks a relation and never removes one. Nothing else in the check changed, and no program or save that restored before is refused now. The regression is `stabilization_trial_a_take_back_after_a_caveated_reopening_restores` in `runtime/tests/take_back.rs`.

Saves written by rc.18 in that situation restore in rc.19.

## The stabilization trial

[experiments/stabilization-trial](https://github.com/WSattazahn/caveat-lang/blob/main/experiments/stabilization-trial/README.md) is the predefined trial Path to 1.0 asks for in stabilization (E2). An installed package drives a deploy gate through the integration starter with a file store: a refusal from each rejection origin, a decision, a restart, a doubt that reopens the decision under the program's policy, the doubt taken back and a new decision, an archive drain across a second restart, and a refused resume under edited source. Each step stays within the trial's own host budgets for send time, checkpoint size and archive size. CI runs it from the packed tarball's fresh install. Its first run, against the published rc.18, found the defect above.
