## New in the language

- `resolve SERIES = VALUE because E [materialized C, …]` records how a
  decision turned out: a value, the evidence it was read from, and which of
  the revision's retained caveats came true. `resolve revision(SERIES, K) = …`
  resolves an earlier revision. The revision's value, basis, caveats and
  status stay as they were, so a review can tell a sound basis that met bad
  luck from an unsound one. A wrong outcome is corrected by withdrawing its
  evidence, after which a new `resolve` replaces it
  ([Outcomes 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-outcomes-0.1.md)).
- `resolved(SERIES)` and `outcome(SERIES)`, and their `revision(SERIES, K)`
  forms, ask whether a revision has an outcome and read it. With
  `latest(SERIES)` they pair a forecast with what happened, so a program can
  score its own forecasts.
- A `resolve` of a revision that already has an outcome is refused as
  `evaluation/already_resolved`, and one that names a caveat the revision does
  not retain as `evaluation/not_retained`. A `resolve` of a series with no
  revision is refused as `evaluation/not_committed`.
- The decision journal gains a `resolved` entry, a save keeps a revision's
  outcome, and `explain` prints it under the revision.

Each form did not load on 1.2.0, so no program that loads there changes
meaning. `resolve`, `resolved`, `outcome` and `materialized` stay legal
names, and a program that defines its own `fn resolved` or `fn outcome`
keeps calling it.

## New in the documentation

- An [authoring card](https://github.com/WSattazahn/caveat-lang/blob/main/kit/docs/AUTHORING_CARD.md)
  puts one program, the commands that check it and the costliest mistakes on
  one page, for an agent writing a program for a task. It ships in the
  package.
- The authoring guide and a new
  [example](https://github.com/WSattazahn/caveat-lang/blob/main/kit/examples/procedure-handles/README.md)
  say when a procedure takes evidence and when it takes a reading stream.
