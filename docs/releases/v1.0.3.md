## A take-back reaches a doubt a plain qualify put on a stored record (D020)

1.0.1's D014 fix lets a `qualify` that comes after a guarded observation reach
the stored observation and predicate qualifications that list the evidence.
It merged the caveat into those records and decided which take-back caveats
the record keeps from the qualify's own guard alone. A `qualify` with no
`when` guard has an empty guard, which lists no evidence, so the record marked
the caveat as kept, as if it had not come through the evidence at all. A later
`unqualify` of that evidence then could not reach it: the current value and
every value read through the record went on carrying the caveat.

Take a program with `on see_e when not observed(e) reveal e supports ok`,
`on flag_e qualify e with flaky`, `on unflag_e unqualify e with flaky` and
`on read set ev = qualified(1, e)`. After see_e, see_e, flag_e, read, the
second see_e has stored a predicate qualification for `observed(e)`, and `ev`
carries `flaky`. In 1.0.1 and 1.0.2, `ev` still carried `flaky` after
unflag_e, and again after another read.

In 1.0.3, the caveat a late `qualify` adds to a stored record is judged with
the evidence it comes through. Every record it reaches already lists that
evidence, so the caveat stays live and a take-back removes it, as it removes
it from the evidence.

**Who can be affected.** Only a program on 1.0.1 or 1.0.2 that has all of
these:

- an `unqualify`;
- a guarded rule that stores a record over a piece of evidence, such as
  `when observed(e)` or `when not observed(e)`;
- a `qualify` of that evidence whose own guard does not read it, most often
  one with no `when` at all.

Such a program's values lose a caveat that a take-back should already have
removed; no refusal changes. A save written by 1.0.1 or 1.0.2 after such a
`qualify` records the caveat as kept in that record and restores as it was
recorded. A host that kept its own event log can repair it by replaying those
events on 1.0.3.

This is finding D020, found by a seeded randomized check of take-back.

## Tests

The fix carries its regression in `runtime/tests/take_back.rs`, named
`d020_a_doubt_raised_after_a_stored_guard_read_the_evidence_can_be_taken_back`,
in the six events above. It fails on 1.0.2 and passes with the fix.

The fix is the same commit as on `main`, picked with `git cherry-pick -x`.
