# caveat-lang 0.1.0-rc.4

The fourth release candidate of the developer kit. It is a **release
candidate, not a stable release**. Like [rc.3](v0.1.0-rc.3.md), it is to be
published to npm with the tag `next`, with the same tarball attached to the
GitHub pre-release `v0.1.0-rc.4`.

**This record was written before publication**, with the pull request that
names the candidate. The release commit is that pull request's merge, so the
[identity](#identity), [gates](#gates) and [npm tags](#npm-tags) below are
marked **TO BE FILLED**, from CI's `kit-package-candidate` for that commit and
from the checks after publication. Until then, rc.4 is on neither npm nor
GitHub, and `npm install caveat-lang@next` installs rc.3.

```sh
npm init -y
npm install caveat-lang@0.1.0-rc.4
npx --no-install caveat init
npx --no-install caveat test umbrella.scenarios.json
```

## What changed since rc.3

Twenty-two pull requests were merged after rc.3, #38 to #62. Each is listed
once below. #41, #43 and #47 are not pull requests; #43 and #47 are issues,
fixed by #50 and #49.

### Refusals that used to end the session

Three kinds of event that were fatal `unclassified` in rc.3 are now refused
with a code of their own, and the session continues. The runtime rolled each
event back in rc.3 as well, but under the
[dispatch contract](../../spec/caveat-dispatch-0.1.md) a fatal outcome ends
the host's session. The diagnostic text is unchanged.

- **`limit/renewal_limit`**
  ([#42](https://github.com/WSattazahn/caveat-lang/pull/42)): a `renew` of a
  renewable evidence that already has its declared number of occurrences. In
  a program with one renewable evidence per subject, such as the agent
  ledger, one subject running out of renewals ended the session for all of
  them.
- **`evaluation/decision_in_force`**
  ([#53](https://github.com/WSattazahn/caveat-lang/pull/53)): a `commit` to a
  decision series whose current revision is still in force, committed and not
  reopened. A full series is still `limit/history_limit`, which is checked
  first. This check comes before a `permitted by` clause's, so such a commit
  is never reported as `not_permitted`.
- **`evaluation/ungrounded_citation`**
  ([#55](https://github.com/WSattazahn/caveat-lang/pull/55)): a `because`
  citation, on a binding or a `set`, that cites evidence or a caveat that what
  it explains never read. Whether a citation holds depends on the session: a
  late caveat can make a declaration win for the first time on a clock tick,
  long after the program loaded. A refused tick advances no time.

### Save and restore

Restore refuses more edited saves. rc.3 accepted each of these:

- **Renewals** ([#50](https://github.com/WSattazahn/caveat-lang/pull/50),
  fixing [#43](https://github.com/WSattazahn/caveat-lang/issues/43)): a
  renewal occurrence in the graph that the save's `renewals` do not list at
  its position. The evidence's next `renew` was then fatal.
- **Reading streams**
  ([#54](https://github.com/WSattazahn/caveat-lang/pull/54)): a reading in
  the graph that its stream does not list at its position, or a stream whose
  occurrences are not its own readings, in order. The stream's next `sample`,
  or the next event that qualified or withdrew its latest reading, could then
  be fatal. The save fuzz now also removes records, and it fails when an
  accepted save makes a later event fatal, not only when the runtime crashes.
- **The sequence and reading dates**
  ([#56](https://github.com/WSattazahn/caveat-lang/pull/56)): a `sequence`
  past 2^53 - 1 (9007199254740991), and a reading dated 0 or past the save's
  `sequence`. A save at the largest sequences made its next events fatal
  ("reactive event sequence exhausted"). A reading's date was not checked,
  unlike a journal entry's or a withdrawal's.
- **Relations and observed evidence**
  ([#57](https://github.com/WSattazahn/caveat-lang/pull/57)): a relation
  between kinds of node that no event relates, such as a commitment relying
  on a claim; a commitment retaining or relying on more than its saved basis;
  and evidence that nothing observes, where the save cites it as a relation's
  target, in a provenance record or in a withdrawal. A later event, such as
  the decision's next revision, could then be fatal.

After #56 and #57, the save fuzz lists no known fatal outcome: for the seeds
it was run with, the default seed and seeds 1 to 7 at 30,000 rounds each, it
meets none. That does not show that restore validation is complete. See
[Known limitations](#known-limitations).

Two fixes change what a session holds as it plays:

- **A new reading of withdrawn evidence is not withdrawn**
  ([#58](https://github.com/WSattazahn/caveat-lang/pull/58)). When a stream's
  template evidence had been withdrawn, a new reading inherited the built-in
  `withdrawn` caveat with no withdrawal record of its own, so the session's
  own save was refused on restore.
- **A zero keeps its sign**
  ([#59](https://github.com/WSattazahn/caveat-lang/pull/59)). A save left out
  a state holding `-0` where the program loads `0`, or the reverse, so the
  restored session held the loaded zero. A binding also kept showing the old
  sign when a state changed only its zero's sign. Both now compare the value's
  bits.

### Repetition, the reader and `caveat check`

- **Every top-level entity counts**
  ([#49](https://github.com/WSattazahn/caveat-lang/pull/49), fixing
  [#47](https://github.com/WSattazahn/caveat-lang/issues/47)). Repetition
  skipped an `entity` statement with a comment inside it, and a last one
  without its `;`, which the loader declares. `$index` then counted fewer
  members than a `kind` event parameter, and a block that selects its member
  with `target == $index` updated another member, or none.
- **The linker, Repetition and the loader read the same statements**
  ([#52](https://github.com/WSattazahn/caveat-lang/pull/52)): braces outside
  `proc` statements and `for` blocks, a comment in a `for` header, a last
  `for` block without its `;`, a module part's last statement, `use` followed
  by a comment, a last statement after `;;`, and a first word that only
  begins with `for`. In a `for` body, a brace in unquoted text pairs only
  within its statement, and text after a block's body is refused with its
  line and column.
- **A `for` body's last statement ends with `;`**
  ([#61](https://github.com/WSattazahn/caveat-lang/pull/61)), whatever the
  number of members, in plain and routed blocks, in a file or a module part.
  No `;` is added. A body with no statement needs none.
- **Routed `for` blocks**
  ([#46](https://github.com/WSattazahn/caveat-lang/pull/46)):
  `for KIND as $NAME routed by P { … };`. Each rule on an event with a
  parameter `P kind KIND` gets `P == $index` at the front of its guard. This
  is routing assistance, not a proof that members are isolated. The profile,
  [Routed Repetition 0.1](../../spec/caveat-routed-repetition-0.1.md), ships
  in the package, and the VS Code grammar highlights `routed by`. rc.3
  refuses a `routed by` header as a malformed `for` block.
- **C003 `unrouted-member-rule`**
  ([#45](https://github.com/WSattazahn/caveat-lang/pull/45)): `caveat check`
  warns about a rule in a plain `for` block, on an event with a parameter of
  the block's kind, that mentions the member but does not select it.
- **C004 `shifted-member-index`**
  ([#62](https://github.com/WSattazahn/caveat-lang/pull/62)): `caveat check`
  warns when a plain block selects its member with `$index` and the event
  numbers that member otherwise, because a `for` block declares an entity of
  the kind before a top-level member. The same pull request documents the
  names the loader accepts (Source text 0.1, "Declared names") and says that a
  brace that is text in a `for` body is written in quotes (Repetition 0.1
  section 2).
- **Two consistency fixes**
  ([#51](https://github.com/WSattazahn/caveat-lang/pull/51)): the grammar
  admits an identifier that begins with `_`, as the runtime always has, and a
  linker error message loses a run of stray spaces.

## Compatibility

These changes refuse programs or saves that rc.3 accepted, or change results.
Each pull request's description has the details and the counts.

**New refusal codes** (#42, #53, #55). `limit/renewal_limit`,
`evaluation/decision_in_force` and `evaluation/ungrounded_citation` replace
fatal `unclassified` outcomes at the same sites. Under the dispatch
contract's versioning rule, each is a new code for a site that was
unclassified; no existing code's meaning or origin changes. A host now gets a
refusal where it got a fatal outcome, and keeps the session. None of the
three is a `policy` refusal, so a scenario's bare `"rejected": true` does not
match them: name the origin. `caveat replay`, `explain` and `dependents` exit
0 where these events made them exit 1. A clock tick refused as
`ungrounded_citation` advances no time, so a program can hold its clock until
another event changes what the tick would show.

**Programs rc.3 loaded that are now refused** (#52, #61). Such a program does
not load, so its saves cannot be restored under the same source. Quoting the
text or adding the `;` corrects the source; it does not migrate a save.

- Rows 10 to 14 of #52's compatibility table, each accepted by the owner, the
  last two on 2026-09-28 as explicit breaking changes:
  - text after a `for` body, as in `} evidence z from w;`, which rc.3 dropped
    silently;
  - a brace pair split across body statements,
    `evidence $p_a from x{; evidence $p_b from y};`, which rc.3 loaded as
    written;
  - a lone `}` in a body statement, `from a}b;`, which rc.3 did not load, or
    loaded other than as written;
  - a `}` then a `{` in one body statement, as in `from }{;`, which rc.3
    loaded as written;
  - a lone `}` in the body's last statement without its `;`, as in
    `from a}b };`, which rc.3 loaded as written with one member, or with a
    body that begins with an empty statement.

  Each loads as written with the brace in quoted text.
- A top-level entity whose name holds a brace, such as `entity north{`, is
  now a member of its kind's blocks (#52). Where its copy needs a reactive
  identifier, such as `state $p_n`, the program does not load ("invalid
  reactive identifier north{_n"). When such an entity came after the block,
  rc.3 loaded the program without copies for it and the members after it.
- A nonempty `for` body whose last statement has no `;` (#61). With two or
  more members, rc.3 loaded it other than as written, because each copy ran
  into the next, or did not load it; a body that begins with an empty
  statement, at the end of the program, loaded as written. With one member,
  rc.3 loaded it as written at the end of the program or part, or with an
  empty statement right after the block. These are refused too: the owner
  accepted this cost on 2026-09-28. The error gives the statement's line and
  column.

**Programs that now load differently** (#49, #52).

- A top-level `entity` statement with a comment inside it, a last one
  without its `;`, or a comment touching the name (`entity north#first`)
  (#49). The skipped member now gets its copy, the members after it their
  right `$index`, and every copy its member's name. The source is unchanged,
  so a save rc.3 made of such a program still matches it. Its restore is
  accepted, and a per-member state keeps the value rc.3 gave the wrong
  member. With per-member reading streams, the restore is refused ("its
  reading streams are not this program's").
- Programs in which rc.3 silently gave members no copy: a brace in a
  statement outside a `proc` or a block, a last statement after `;;`, or a
  first word that only begins with `for` (#52). Every member now gets its
  copy. A save rc.3 made restores, and reads lost before stay lost; a
  per-member state of a member that had no copy starts at 0. With per-member
  reading streams, the restore is refused.
- A module part that ends in unquoted provenance without its `;` (#52). The
  provenance now reads as written, `"field notes"` rather than
  `"field notes origin main"`, and the main program's declarations are
  attributed to `main`, not to the module. A save made before the change
  restores.
- Programs rc.3 refused that now load: a comment in a `for` header, a last
  `for` block without its `;`, and the other shapes in the Changes of
  [Repetition 0.1](../../spec/caveat-repetition-0.1.md#changes).

**Saves rc.3 restored that are now refused** (#50, #54, #56, #57). These are
edited saves: saves the runtime writes restore as before, with one edge. A
session resumed from an edited save at or near the sequence bound numbers its
events past 2^53 - 1, and its own saves from then on are refused (#56). Some
of the newly refused saves played on in rc.3 with no fatal outcome: one with
a reading dated 0 or past its `sequence` (#56), one from which a reveal
relation was removed while a record still cites that evidence, and one whose
commitment retains or relies on more than its basis (#57). A refused save is
a restore failure (the kit's `CaveatError` of kind `"restore"`), not a
dispatch outcome.

**Results that change** (#58, #59).

- A reading sampled from a stream whose template evidence was withdrawn no
  longer carries `withdrawn`: in the graph, its archive, `latest(S)`, and the
  basis and `retains` relations of a decision made on it. So
  `has_caveat(value, withdrawn)` on a value taken from it is now false, and a
  guard on it can change outcome; the kit's explain report no longer lists
  the caveat for it. `withdrawn(latest(S))`, `rests_on_withdrawn` and
  permission checks read the withdrawal records and are unchanged. A save an
  earlier runtime wrote with such a relation is still refused, as it was.
- A state that holds `-0` where the program loads `0`, or `0` where it loads
  `-0`, is now in the save and restores with its sign, and bindings show its
  sign. Snapshots, views and saves of such sessions change. A save rc.3
  wrote that left such a state out restores as it did, to the loaded zero.
  `JSON.stringify` writes `-0` as `0`, so a host should store the text
  `save()` returns.

**`caveat check`** (#45, #62). C003 and C004 are warnings. A program that
checked clean with rc.3 may now warn, and then fails with `--strict`. Of the
repository's programs, only Trail Rescue gets a new warning: C003, on two
rules that reset every tunnel's tallies on purpose.

**Messages.** Some errors for programs and saves that rc.3 already refused
have new text (#51, #52, #57).

## Known limitations

Left for separate decisions; none is changed by this candidate.

- **A state's grounds are not checked against its lineage on restore**
  (#55). An edited save whose state cites grounds outside its lineage is
  accepted, and the next event that shows a binding `because` that state is
  refused as `ungrounded_citation`, where the original session accepts it.
  Commitment grounds get past the same check when the journal's `because` is
  edited to match.
- **A scheduled built-in `withdrawn` in an edited save** (#57, #58). Restore
  accepts a scheduled qualification whose caveat is `withdrawn`. When it
  comes due, it qualifies evidence with no withdrawal record, and the
  session's own next save is refused ("withdrawals disagree with the graph's
  withdrawn relations"). Only an edited save can hold one.
- **The decision journal's restore checks ignore a zero's sign** (#59). An
  edited save whose journal entry has elapsed time `-0.0` against `0.0`, or a
  value `-0.0` against its commitment's `0.0`, is accepted.
- **A provenance-limit error during an event is fatal** `unclassified`
  (#57). #57 closed only the restore path to one.
- **The frozen glowcap programs reach a fatal outcome in random play**
  (#57). `experiments/glowcap/caveat` and `caveat2` reached "cannot qualify a
  value with unobserved evidence" (`taste_*` events). It was not
  investigated.
- **A reading inherits the caveats of its template's first occurrence**
  (#58). For renewable template evidence, a reading inherits the caveats of
  the declared node, the first occurrence, not the current one, so it can
  carry a caveat added to the first occurrence and miss one added to the
  current occurrence. The specs do not settle which is meant.

The save fuzz has no known fatal outcome for the seeds it was run with. That
is not proof that restore validation is complete: the edited saves above
pass restore, and each pull request lists what it found and did not fix,
some of which later pull requests in this list fixed.
