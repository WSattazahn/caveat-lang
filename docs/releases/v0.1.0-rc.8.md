# CAVEAT Language 0.1.0-rc.8 — verified publication

rc.8 is published on npm under `next`; `latest` remains rc.5. This candidate
strengthens saved-state validation and adds a checked Lean model with a bounded
comparison against the production runtime. The [GitHub prerelease](https://github.com/WSattazahn/caveat-lang/releases/tag/v0.1.0-rc.8)

remain unchanged.

## Changes

### Reject unrelated grounds in edited saves

An edited save could attach observed but unrelated evidence, or a declared but
unrelated caveat, to a value's selected grounds. Restore now checks state grounds
against saved lineage and commitment grounds against the frozen commitment
basis. Invalid additions are refused during restore.

The checks preserve valid narrowed grounds, omitted optional grounds, and
historical commitment bases when current qualifications have changed. They
validate consistency of the saved record; they do not authenticate its evidence
or establish how a saved state was reached.

Implemented in [PR #87](https://github.com/WSattazahn/caveat-lang/pull/87).

### Check dependency laws and production-runtime agreement

The development-only verification project pins Lean **4.34.1** and uses its
bundled libraries. It adds no npm runtime dependency to the published kit.

- **58 authored laws** cover exact dependency flow, selected grounds, successful
  and skipped guarded assignments, citations, and separate Accepted, Rejected,
  and Fatal outcomes. Nonempty witnesses make erased dependencies detectable.
- The proof gate inventories **128 public theorems**, audits transitive axioms
  across all public project declarations, replays the project modules through
  Lean's kernel, and requires incomplete-proof and custom-axiom controls to fail.
- A compiled runner executes the same Lean definitions being proved. The
  comparison exercises **53 deterministic cases** through native Rust and the
  production WebAssembly session API: **97 accepted and 24 rejected modeled
  steps**, exact values and both dependency channels, ordered observations and
  effects, complete native/WASM captures, rejection rollback, one-event
  continuation from every restored prefix, and a final save/restore check.
- **18 decoder refusal controls** check the runner's input boundary. Five
  semantic mutation families require their intended discrepancies across nine
  executions, including a compiled production-Rust mutation that drops the same
  dependency from both lineage and grounds. A crash or malformed result fails
  the infrastructure instead of counting as mutation detection.
- Four real WASM overflow cases cover both dispatch methods and both provenance
  capacity limits, including Fatal disposal and refusal to reuse the session.
  Build-input fingerprints and generated JS/WASM hashes are checked before and
  after the comparison. Linux CI enforces the complete gate.

Implemented in [PR #88](https://github.com/WSattazahn/caveat-lang/pull/88).
The [verification contract](../../spec/caveat-verification-0.1.md) and
[Lean guide](../../proofs/lean/README.md) define the model, commands, assumptions,
and required controls.

## Scope

The executable comparison covers state reads, eager addition, guarded
assignments and state citations over bounded exact integers. Its neutral
observation initialization is a fixed fixture. It excludes arbitrary or lazy
expressions, fractional arithmetic, dynamic observation and qualification,
withdrawal, readings, commitments, and historical journal semantics.

The general Lean laws and separate runtime boundary tests have their own
scopes. Sampled executable agreement is not a Rust refinement proof. JSON and
source adapters, generated machine code, general floating-point behavior, and
save validation are not formally proved. Native Rust and WASM share the
production interpreter.
