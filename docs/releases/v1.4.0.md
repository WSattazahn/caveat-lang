1.4.0 is the fourth minor release of 1.x. It is cut from `main`. It adds six
language profiles and two kit reports, four refusal codes (two for new syntax,
two for inputs that ended the session before), two library exports and a
what-if check. It fixes two bugs that made a session write a save it could not
restore (D021) or end the session on a large expression (D022, D023), and one
where a reading missed a caveat it should have carried (D024). A program that
loads on 1.3.0 loads on 1.4.0 and computes, accepts, refuses, saves and
explains the same as before, byte for byte, apart from those fixes. A save
written by 1.3.0 restores the same on 1.4.0. The profiles it adds are stable
from 1.4.0 under the
[compatibility commitment](https://github.com/WSattazahn/caveat-lang/blob/main/docs/COMPATIBILITY.md).

## New in the language

- `agent NAME sends EVENT, …;` says which agent may send which event. A host
  passes `{ agent }` to `dispatch`; an event sent by an agent the program does
  not allow is refused as `input/wrong_agent`, and an accepted event's record
  carries its agent. Programs with no `agent` declaration are unchanged
  ([Agents 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-agents-0.1.md)).
- `withdraw every NAME because EVIDENCE` withdraws everything a source said,
  and `retaining CAVEAT because once EVIDENCE` makes a confirmation count for
  one commit only; reusing it is refused as `evaluation/reason_spent`.
  `undoList(snapshot)` in `caveat-lang/explain` and `caveat undo-list` list
  every revision, current or past, that went out on evidence since withdrawn
  ([Untrusted Sources 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-untrusted-sources-0.1.md)).
- `only_if(CONDITION, VALUE)` gives `VALUE` when the condition holds and `0`
  otherwise. What the condition reads counts as lineage, not grounds, so a
  decision on several sources' votes rests only on the votes that agreed
  ([Only If 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-only-if-0.1.md),
  [model-votes example](https://github.com/WSattazahn/caveat-lang/blob/main/experiments/model-votes/README.md)).
- `carries_any(E)` and `carries_any(E, CONSEQUENCE)` ask whether evidence
  carries any caveat, or any at that consequence or worse, so a guard need not
  list every caveat by name
  ([Carries Any 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-carries-any-0.1.md)).
- `decisions NAME limit N forecloses ACTION, …` lets a decision that can be
  undone rule options out while it is in force; once it is reopened they are
  open again. A foreclosed commit is refused as `evaluation/foreclosed`, as in
  1.2.0
  ([Foreclosure 0.2](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-foreclosure-0.2.md)).
- `decisions NAME limit 1 irreversible strict` refuses an irreversible commit
  as `evaluation/caveated_irreversible` when anything it read, its guard and
  `permitted by` grant included, carries an unretained caveat of consequence
  `material` or worse
  ([Strict Irreversible 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-strict-irreversible-0.1.md)).

Each form did not load on 1.3.0, so no program that loads there changes
meaning. The words they use stay legal names.

## New in the kit

- `caveat review PROGRAM SERIES@N EVENTS` and `review(…)` say which evidence
  a decision hinged on, by replaying the events without each piece
  ([Review 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-review-0.1.md)).
- `caveat review --all DIRECTORY` and `reviewLedgers(…)` review every resolved
  decision across many ledgers, and a decision can record that it consulted a
  past review
  ([Ledger Sets 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-ledger-sets-0.1.md)).
- `session.whatIf(event, payload, { fields })` runs an event on a dropped copy
  of the session and returns what `dispatchView` would, leaving the session
  unchanged. The runtime gains `what_if_view_outcome` and
  `what_if_view_fields_outcome`.
- `caveat-lang/handoff`: `scopeSession` limits a session to some events, and
  `replayOnto` replays accepted events into another session
  ([handoff example](https://github.com/WSattazahn/caveat-lang/blob/main/kit/examples/handoff/README.md)).
- `caveat-lang/saves`: `savedEvents` reads a replay save's events back by
  name, and `carrySave` replays a save onto a changed program.
- Load errors give the line and column and suggest the closest declared name
  or keyword; a statement starting with `--` says `--` is not a comment;
  payload and save errors name what was expected; the CLI suggests the
  nearest command or option. Messages only: codes, exit statuses and outputs
  are unchanged.
- `explain` marks an accepted event "accepted as #N" after a refusal.
- `caveat doctor` compares the runtime's hashes, and `init` errors are one
  line.
- The MCP server's five tools are unchanged; `caveat_test` describes binding
  pointers.

## Fixed

- **D021.** Sessions under 1.2.0 to 1.3.0 that used holds with a reopening
  could write a save that will not restore ("decision journal: entry
  witnesses are unobserved, repeated, or out of order"). 1.4.0 writes the
  causes in observation order, so new saves restore. Saves already written
  that way still refuse, because restore never repairs a save: replay that
  session's events on 1.4.0 to get a good save.
- **D022, D023.** An event whose expression would give a value a lineage of
  more than 1,024 identifiers, or visit more than 65,536 nodes, ended the
  session. It is now refused as `limit/provenance_limit` or
  `limit/evaluation_limit`, and the session goes on
  ([Dispatch 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-dispatch-0.1.md)).
- **D024.** Readings sampled from renewable evidence now also inherit the
  caveats qualifying the current occurrence when the sample is taken. No new
  code and no new snapshot or save field; the corpus sweep is identical to
  1.3.0's.

## New in the documentation

- A [15-minute tutorial](https://github.com/WSattazahn/caveat-lang/blob/main/docs/tutorials/agent-undo-list/README.md)
  builds an agent with an undo list, and CI runs every step of it.
- A [game developer guide](https://github.com/WSattazahn/caveat-lang/blob/main/kit/docs/GAMES.md),
  a tested hello, world, and examples for retracted studies and the intel
  betrayal.
- A security policy and threat model, which says records hold evidence in
  plain text and that an event's agent is the host's word; each GitHub release carries a bill of materials.
- The compatibility commitment names visible behaviors 1.x does not promise.
- Design notes on graded belief, and related work beside bitemporal
  databases, legal citators and retraction trackers.
