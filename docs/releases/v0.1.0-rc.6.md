# caveat-lang 0.1.0-rc.6

The sixth release candidate of the developer kit. It is a **release
candidate, not a stable release**. Like [rc.5](v0.1.0-rc.5.md), it is to be
published to npm with the tag `next`, with the same tested tarball attached
to its GitHub pre-release. It has **not been published**. Until then,
`caveat-lang@next` installs rc.5.

**This record is prepared before publication.** The changes, compatibility
and known limitations are written with the release-preparation pull request.
Its merge is to be the release commit, so the tag will carry them. The
[identity](#identity), [gates](#gates) and [npm tags](#npm-tags) are to be
completed from CI's tested candidate for that commit and from checks on what
npm and GitHub serve.

Once published:

```sh
npm init -y
npm install caveat-lang@0.1.0-rc.6
npx --no-install caveat init
npx --no-install caveat test umbrella.scenarios.json
```

## What changed since rc.5

- **An agent-evidence starter in the package**
  ([#72](https://github.com/WSattazahn/caveat-lang/pull/72)).
  `examples/agent-evidence/` contains a Caveat assessment program, a Python
  client for `caveat serve`, its tests and instructions. The client uses
  Python's standard library and requires Python 3.9 or later. It separates
  a handled request, an accepted event and an application assessment that
  permits the intended result. Its `Attempt` records required operations;
  an earlier approval cannot make a later rejected, failed or unfinished
  required operation count as success. It allows one attempt at a time per
  server and keeps an unfinished send from becoming the next attempt's
  evidence. The packaged tests run against a real server. The language
  reference also explains three integration mistakes: giving `tick`
  parameters other than its permitted `dt`, assigning conflicting
  program-wide member constants through reused parameter names, and naming
  an event parameter like an existing state or coordinate.
- **TypeScript declarations and bundler import hints**
  ([#73](https://github.com/WSattazahn/caveat-lang/pull/73)).
  Each of the six library entry points, `session`, `node`, `scenarios`,
  `explain`, `serve` and `check`, now names its `.d.mts` declarations through
  the `types` condition of `exports`, before `default`. The package also
  ships wasm-bindgen's `runtime/caveat_runtime.d.ts`. The declarations cover
  sessions, outcomes, errors, snapshots, views, options and reports. The two
  URL-based `import()` calls in `loadRuntime` carry webpack and Vite ignore
  comments. A bundled host can import the runtime module itself and pass its
  namespace; a runtime URL is left to the platform to load.
- **The generated runtime declares its disposal type dependency**
  ([#75](https://github.com/WSattazahn/caveat-lang/pull/75)).
  After wasm-bindgen emits each runtime, the build adds a reference to
  TypeScript's `esnext.disposable` library at the start of its `.d.ts` file.
  Its generated `Symbol.dispose` member otherwise fails a strict consumer
  using only `ES2022` and `DOM`. This applies to both full and reactive
  runtime declarations before packaging; it does not change their JavaScript
  or WebAssembly.
- **Links that work from an installed package**
  ([#74](https://github.com/WSattazahn/caveat-lang/pull/74)).
  When packing the copied reference documents, a relative link to a
  repository file that is not included in the package becomes a GitHub URL
  at the full build revision from `build-info.json`. Links to shipped files
  stay local. Absolute URLs, same-page anchors and links inside fenced or
  inline code are left alone. The package test checks the rewritten copies
  and requires every relative file link in installed Markdown to resolve
  inside the package; an existing file outside it cannot satisfy the check.
  Its report counts the rewritten links. The package README now points to
  the shipped Scenarios and dispatch specifications and thermostat example,
  and gives the installed path from which to copy that example.

[#71](https://github.com/WSattazahn/caveat-lang/pull/71) recorded rc.5 as
published and set the development package version to rc.6. It did not add a
runtime feature.

The package adds 11 files to rc.5's 59: the four agent-evidence files, six
library declarations and one runtime declaration. The final file count,
tarball size and changed-file list are **TO BE FILLED** from the release

## Compatibility

This candidate adds examples, declarations and documentation packaging, and
adds bundler comments to the session loader. It contains no Rust runtime or
language specification changes.

**JavaScript imports.** The six public subpaths keep their `.mjs` default
targets; their export entries now also name their declarations. The runtime
wildcard export remains available. The Node requirement remains 20 or later,
and the package has no runtime npm dependencies. Python is needed only to
use or test the new Python example.

**TypeScript consumers.** The declarations support `bundler`, `node16` and
`nodenext` module resolution. The repository tests their names, object
members, codes and kinds against the implementation; they do not run a
TypeScript compiler or compare every parameter and return type. The built
runtime declarations also have a regression check for their disposal library
reference.

Manual compiler probes use TypeScript 6.0.3 with `strict: true`,
`skipLibCheck: false`, no ambient `types`, and the `ES2022` and `DOM`
libraries. They cover `bundler` and `nodenext` resolution, all six library
entry points, both loaders, accepted and rejected `dispatchView` results,
fatal error reports and expected errors for invalid payloads and a
rejection's nonexistent view. The consumer does not need to name
`ESNext.Disposable` itself. A minimum supported TypeScript version has not
been established. The release commit's verification is recorded below.

**Runtime loading.** URL loading and passing an imported module namespace
remain supported. A namespace cannot be imported afresh after its WebAssembly
instance traps; recovery needs a runtime module URL. The bundler comments
apply to both the initial URL import and the fresh-instance import.

**The starter.** rc.5 does not ship the `examples/` directory; its documented
fallback is to copy the example from the repository. The starter uses the
existing `caveat serve` protocol and defines its own application policy.

**Documentation.** Packing changes links in the copied Markdown. A reference
to an unshipped file opens GitHub at the build's revision and needs network
access. The link checks cover file targets, not heading anchors or external
website availability.

## Known limitations

[rc.5's limitations](v0.1.0-rc.5.md#known-limitations), including the
linked rc.4 runtime limitations, remain outside this candidate's changes.

The starter trusts the evidence the application sends. Labels do not
authenticate evidence. It has no receipt store, hashing or binding to
files; the host decides what records to keep and what an assessment permits.
Its sample session holds at most 16 observations and 8 assessments; reaching
a limit requires the application to start a new server to continue. The
caller supports one attempt at a time on a server, and callers must close
the server or leave its context manager.

Host conformance tests remain a future item.
