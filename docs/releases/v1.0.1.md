# CAVEAT Language 1.0.1

**Candidate, not yet published.** This note becomes the release record once
npm publication of caveat-lang@1.0.1 is verified.

1.0.1 is a patch release of 1.0.0. It contains one runtime fix, and nothing else
from later work on `main`. It is cut from the maintenance branch `release/1.0.x`,
which starts at the [1.0.0 release](https://github.com/WSattazahn/caveat-lang/blob/main/docs/releases/v1.0.0.md).
It adds no language syntax, schema, runtime operation, field, CLI flag, export,
MCP tool or tool argument, and no rejection code.

## A take-back now reaches a doubt carried through a guarded renewal

In 1.0.0, an `unqualify` could miss a doubt that a renewal's guard had copied
into the new occurrence. Take this program:

```caveat
caveat flaky consequence material;
evidence e from "tool";
renewable e limit 8;
event report;
event flag;
event unflag;
on report when observed(e) renew e;
on report reveal e;
on flag qualify e with flaky;
on unflag unqualify e with flaky;
state v = 0;
on report set v = qualified(1, e);
```

After the events report, flag, report, flag, unflag, neither occurrence of `e`
carries `flaky` any more, but 1.0.0 still reported `has_caveat(v, flaky)` as 1.
The renewal's guard read `observed(e)` while the first occurrence was doubted,
and the runtime stored that doubt in the new occurrence's record as if a record
had kept it. Every later read of the occurrence then took the doubt back in.

In 1.0.1, `has_caveat(v, flaky)` is 0 after the take-back, matching the
occurrences, and a value read again afterwards agrees.
[Take-back 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-take-back-0.1.md),
step 3, already promised this: later reads "no longer take the caveat through a
marked relation". The spec's "Kept caveats" section now states the rule for
stored observation and predicate qualifications.

**What does not change.** A decision committed while the doubt was live still
keeps it in its basis, and so does anything read from that basis. Commitment
bases and grounds, archives, the journal, and selection and reopening records
keep what they recorded, as before.

**Who sees a difference.** Only a program that has both of these:

- an `unqualify`;
- a `renew`, `reveal`, `observe` or `sample` rule whose guard read evidence
  while it carried the caveat being taken back, such as
  `when observed(e)` on a doubted `e`.

Search a program for `unqualify`. If it has one, look for those rules' guards
on the same evidence. Under
[COMPATIBILITY.md](https://github.com/WSattazahn/caveat-lang/blob/main/docs/COMPATIBILITY.md)'s
versioning policy, this is a 1.x patch: a fix that makes behavior match a
documented promise.

**Check your runtime in one run.** Copy
[v1.0.1-d012.cav](https://github.com/WSattazahn/caveat-lang/blob/main/docs/releases/v1.0.1-d012.cav)
and
[v1.0.1-d012.scenarios.json](https://github.com/WSattazahn/caveat-lang/blob/main/docs/releases/v1.0.1-d012.scenarios.json)
into a directory and run `npx caveat-lang test v1.0.1-d012.scenarios.json`
there. 1.0.0 fails its last expectation, and 1.0.1 passes it.

**Saves written by 1.0.0.** 1.0.1 restores every 1.0.0 save unchanged and
refuses none. A save written after the bug fired still holds the stale doubt,
and a later guarded renewal can carry it into new occurrences. The loader does
not repair it, because a stale doubt cannot be told apart from a caveat a
record legitimately keeps.

A save can be affected only if all of these hold:

- its program has the shape above;
- a guard read the doubted evidence;
- the `unqualify` came before the save.

To look for one, check the save for an `observation_qualifications` or
`predicate_qualifications` record whose `kept` lists a caveat while its
`evidence` lists an occurrence that `taken_back` names for that caveat. This
check can flag a save that is not actually affected.

To repair an affected session, replay its events on 1.0.1. Without an event
log there is no repair in place. The affected values keep showing the
taken-back doubt, which errs on the side of caution.

This is finding D012 in
[the agent-decisions log](https://github.com/WSattazahn/caveat-lang/blob/main/experiments/agent-decisions/README.md).
Its tests are in `runtime/tests/take_back.rs`, adapted to 1.0's syntax, which
cannot name an earlier occurrence:

- the D012 regression;
- a check that a decision made while flagged keeps the flag;
- a randomized check of 200 event sequences. After every event, it asserts
  that each value carries `flaky` exactly when evidence it rests on still
  carries it.

## Release process

The publish workflow now also accepts a tested Runtime run from a push to a
`release/MAJOR.MINOR.x` maintenance branch, not only from `main`. Every other
publication check is unchanged: the annotated tag, the exact tested bytes, the
owner's approval and the provenance.

## Install

```sh
npm install caveat-lang@1.0.1
```
