## Release procedure

Use the current installed kit (historical consolidation text predates it).
Reactive-only lint/tests, package and security gates now run in Runtime CI.
Retain exact revision, run/attempt, artifact IDs, package/security reports,
build-info, tool/lock identities, SHA256, SHA512 and npm integrity in durable
GitHub prerelease assets. Annotate v0.1.0-rc.7 at the verified final-main revision
only after Runtime and Pages/live gates pass. Mark GitHub release prerelease and
state npm publication pending. Do not delete stack branches or rewrite history.

The owner will publish only the retained tested tgz to the official registry
with `--access public --tag next`; no automatic npm action is authorized. Before
publication, verify immutable asset hashes and package/runtime identity. After
publication, verify registry integrity, fetched bytes and an exact-version fresh
install (both aliases, doctor, demo and umbrella scenarios) before recording
npm availability. A same-version retry is permitted only for identical bytes.
Leave `latest` unchanged. Then update factual publication records and public
installation examples. Start rc.8 development only after rc.7 tag/assets freeze.
