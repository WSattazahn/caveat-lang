1.2.0 is the second minor release of 1.x. It is cut from `main`. It adds three
language forms, nested `for` blocks, holds and foreclosure, a smaller replay
save and a way to ask for only some view fields, and it adds two rejection
codes, both for the new syntax. A program that loads on 1.1.0 loads on 1.2.0
and computes, accepts, refuses, saves and explains the same as before, byte
for byte. A save written by 1.1.0 restores the same on 1.2.0. Every profile
it adds is stable from 1.2.0 under the
[compatibility commitment](https://github.com/WSattazahn/caveat-lang/blob/main/docs/COMPATIBILITY.md).

## New in the language

- A `for` block inside a `for` block, plain or routed, to any depth. A rule
  about a pair, such as a component and one of its decision numbers, is
  written once
  ([Nested Repetition 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-nested-repetition-0.1.md)).
- `hold SERIES because …`, `release SERIES because …` and `on_hold(SERIES)`:
  keep a decision in force for a while. A reopening that arrives during the
  hold, by a rule or a trigger, is deferred and recorded; `release` applies
  every deferred reopening. A revision that rests on withdrawn evidence is
  never held. The decision journal gains `held`, `deferred` and `released`
  entries, and a save keeps a hold and what it deferred
  ([Holds 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-holds-0.1.md)).
- `decisions NAME limit 1 irreversible [forecloses ACTION, …]`: a decision
  that cannot be undone, and the actions it closes off. Once it is committed,
  a `commit` of a foreclosed action is refused as `evaluation/foreclosed`,
  and a hold never lifts what it closed off. An irreversible commit that rests
  on a caveat of consequence `material` or above, not named in its
  `retaining` clause, is refused as `evaluation/caveated_irreversible`
  ([Foreclosure 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-foreclosure-0.1.md)).

Each form did not load on 1.1.0, so no program that loads there changes
meaning. The new words are read only in their positions: a series, stream or
claim named `irreversible` or `forecloses` keeps loading.

## New in the kit

- `session.save({ compact: true, positional: true })` writes a
  [positional replay save](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-replay-save-0.2.md),
  `caveat-replay-save/0.2`, which holds more events in the same 4,096 bytes. `runtime.restore` takes it like any save; a runtime before
  1.2.0 does not. `save()` and `save({ compact: true })` are unchanged byte
  for byte.
- `session.dispatchView(event, payload, { fields })` returns a view with only
  the named fields, and the runtime builds no others
  ([View 0.1](https://github.com/WSattazahn/caveat-lang/blob/main/spec/caveat-view-0.1.md),
  "Selected fields"). `VIEW_FIELDS` lists the names.
- `decisionHistory` and the TypeScript declarations know the new journal
  entries and a series' `on_hold` and `deferred`, and `explain` says which
  series are irreversible, what each forecloses and what foreclosed it.

## Inside the runtime

Bindings are evaluated again only when their histories change, provenance
name sets are shared between values, reads that rest on nothing skip
provenance work, and the view delta is built from text. Outputs are
unchanged; the tests below compare them.
