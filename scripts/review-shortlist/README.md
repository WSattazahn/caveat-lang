# What in this pull request does a person still need to check?

When a coding agent writes a pull request, nobody may have read most of it.
Caveat can't do the reading. It can shrink what has to be read: it keeps,
for each changed file, what that change rests on, and lists only the files
that rest on nothing but the agent's own word, or on a test or spec that has
changed since.

```
node scripts/review-shortlist/shortlist.mjs 371
node scripts/review-shortlist/shortlist.mjs 371 --json
node scripts/review-shortlist/shortlist.mjs 349 --out /tmp/pr-349   # also writes program.cav, events.jsonl, facts.json
```

Run it in a clone of the repository (it fetches the pull request's head and
main with git), after `npm run build`, or with `CAVEAT_SHORTLIST_KIT` naming
a caveat-lang package folder. In a Claude session, run it with
`NODE_USE_ENV_PROXY=1 NODE_EXTRA_CA_CERTS=/root/.ccr/ca-bundle.crt` and no
`GITHUB_TOKEN`. It reads; it changes nothing on GitHub and blocks nothing.

## What a file rests on

| Fact | Where it comes from | Takes the file off the list? |
| --- | --- | --- |
| who wrote it | the pull request's author, a "Generated with" line or a `Co-authored-by` trailer naming an agent (the [PR ledger](../../actions/pr-ledger/README.md)'s `authorOf`) | a person's change, yes; an agent's carries `unreviewed` |
| a person's review | an approving review at the head, or a review comment on the file, by an account that is not a bot and without an agent's "Generated by" footer | yes |
| a test from before the pull request | a test file the pull request didn't touch that names the file (its base name with extension, as an import or a path spells it), with every check on the head passing | yes |
| a test the pull request adds or changes | the same, for a test file the pull request changes | no: it is the agent's word too (`agent_written`) |
| a spec | a `spec/` document the file names that the pull request changes or its description cites | no: a spec says what was meant, not that the change does it |
| a change on main since | a later commit on main to a test or spec the file rested on (since the merge, or since the branch point while open) | puts the file back on the list, reviewed or not |

Each file is one decision in a copy of
[`shortlist.cav.template`](shortlist.cav.template), with one entity per
changed file, test and spec. Its grounds are frozen when it is decided, so a
later change to a test or spec withdraws that evidence instead of rewriting
anything, and the file reopens. `caveat undo-list` and `caveat dependents`
on the `--out` folder say the same thing in Caveat's own words.

## On this repository's pull requests

Every recent pull request here was written by an agent and merged without a
review, so the list is long: #371 lists 9 of its 10 files, and #373 and
#366, which each add one test, list that test. That is the honest answer
for this repository today. What the list adds is which files, and why:
#371's runtime workflow change is off it because existing tests read that
file, while its new page is backed only by the test the agent wrote with it.
For a merged pull request such as #349, it also names the tests and specs
that have changed on main since, and which files rested on them.

## What it does not do

- It guesses which tests cover a file from whether they name it. A test can
  name a file without testing the lines that changed (#371's workflow file
  is read by tests that don't check the new step), and a test can cover a
  file without naming it (Rust tests don't name source files).
- Who wrote what is what the pull request says. An agent that leaves out its
  trailer, or posts through a person's account without its footer, counts as
  a person.
- A person's comment on a file counts as review of that file. It says
  someone looked, not that they understood or agreed.
- It treats the whole pull request as written by one author, and a file as
  one claim. It does not split a file into hunks.
- It takes at most 300 changed files.

`npm run test:review-shortlist` checks the program, runs its scenarios
([`fixture.scenarios.json`](fixture.scenarios.json), on
[`fixture.cav`](fixture.cav), the template rendered for four files) and the
host's tests ([`shortlist.test.mjs`](shortlist.test.mjs)) against fakes of
GitHub and git.
